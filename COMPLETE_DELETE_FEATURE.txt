                           BACKEND CHANGES
================================================================================

FILE: backend/server.ts

NEW ENDPOINT:
─────────────────────────────────────────────────────────────────────────────

DELETE /api/sales/:id

Route Definition:
  app.delete('/api/sales/:id', authenticate, async (req, res) => { ... })

Authentication: Required (Bearer token)

Functionality:
  1. Validates bill exists
  2. Begins database transaction
  3. Fetches bill items from database
  4. For each item:
     - Increases product stock quantity
  5. Deletes all bill items
  6. Deletes bill record
  7. Commits transaction

Error Handling:
  - If bill not found: Returns 404
  - If any error occurs: Rolls back entire transaction
  - Returns appropriate error message

Database Operations:
  ───────────────────────────────────────────────────────────────────
  1. SELECT bill WHERE id = ?
  2. SELECT billItems WHERE billId = ?
  3. UPDATE products SET currentStock = currentStock + ? (for each item)
  4. DELETE FROM billItems WHERE billId = ?
  5. DELETE FROM bills WHERE id = ?

Transaction Guarantee:
  All operations succeed or all roll back (ACID compliance)

Response Format:
  Success (200):
    { "message": "Bill deleted successfully" }
  
  Not Found (404):
    { "error": "Bill not found" }
  
  Server Error (500):
    { "error": "Failed to delete bill" }

IMPORTANT: Stock Restoration
───────────────────────────────────────────────────────────────────────────
When a bill is deleted, the quantities are automatically restored to product
inventory. This prevents inventory inconsistencies.

Example:
  Before bill: Product A has 100 units
  Create bill: Sell 5 units → Product A has 95 units
  Delete bill: → Product A has 100 units (restored)
